SECTION 1: PROJECT OVERVIEW & MOTIVATION
================================================================================

Q1. What is the main problem your project addresses?
ANSWER: Traditional IP registration systems are centralized, slow, costly, and 
limited by jurisdiction. There's no global mechanism to verify IP ownership 
instantly. Our project provides a decentralized, blockchain-based solution for 
secure IP registration, verification, and marketplace transactions.

Q2. Why did you choose blockchain technology for IP protection?
ANSWER: Blockchain provides:
- Immutable ownership records that cannot be tampered with
- Transparent verification accessible globally
- Decentralized storage eliminating single points of failure
- Smart contract automation for trustless transactions
- Timestamped proof of creation and ownership

Q3. What are the key objectives of your project?
ANSWER:
1. Develop blockchain-based system for secure IP registration and verification
2. Implement smart contracts for ownership records and on-chain verification
3. Build decentralized marketplace for buying, selling, and licensing IP assets
4. Create user-friendly Web3 platform with category-wise IP display

Q4. Who are the target users of your platform?
ANSWER: Three main user roles:
- Creators: Register and protect their intellectual property
- Buyers: Purchase or license IP assets securely
- Administrators: Verify trademarks, moderate content, handle reports

================================================================================
SECTION 2: BLOCKCHAIN & SMART CONTRACTS
================================================================================

Q5. Which blockchain network did you use and why?
ANSWER: Polygon (formerly Matic). Reasons:
- Low transaction fees compared to Ethereum mainnet
- Fast block confirmation times (2-3 seconds)
- EVM compatibility - can use Solidity and Ethereum tools
- Good for academic projects with limited budgets
- Supports ERC-721 NFT standard

Q6. Explain the smart contracts in your project.
ANSWER: Two main contracts:
1. TrademarkNFT.sol - Handles IP registration as NFTs with ERC-721 standard
2. TrademarkMarketplace.sol - Manages listings, sales, and licensing

Q7. What is ERC-721 and why did you use it?
ANSWER: ERC-721 is the NFT standard for unique, non-fungible tokens. Each 
trademark is unique and needs individual representation, making ERC-721 perfect 
for IP assets. It provides standard functions like ownerOf(), transferFrom(), 
and supports metadata through tokenURI.

Q8. Explain the registerTrademark function in your smart contract.
ANSWER: The registerTrademark function:
- Takes trademark details (company name, slogan, registration number, etc.)
- Mints a new NFT with unique tokenId
- Stores trademark information on-chain
- Sets royalty percentage for creator (EIP-2981 standard)
- Stores IPFS hash linking to off-chain metadata
- Emits TrademarkRegistered event for indexing
- Returns tokenId for reference

CODE REFERENCE: contracts/TrademarkMarketplace.sol, TrademarkNFT contract

Q9. What security measures are implemented in your smart contracts?
ANSWER:
- ReentrancyGuard: Prevents reentrancy attacks on payment functions
- Ownable: Restricts admin functions to contract owner
- Input validation: Checks for zero addresses, valid amounts
- Access control: Only trademark owner can list their assets
- Safe transfers: Uses safeTransferFrom for NFT transfers
- Expiration checks: Validates listing expiration before transactions

Q10. How do you handle royalties in your marketplace?
ANSWER: Using EIP-2981 royalty standard:
- Creators set royalty percentage (in basis points) during registration
- royaltyInfo() function calculates royalty amount for any sale price
- During sale, royalty is automatically deducted and sent to creator
- Marketplace fee is separate from royalty
- If seller is the creator, royalty is added back to their payment

Q11. Explain the difference between buying and licensing in your marketplace.
ANSWER:
BUYING (Full Sale):
- Complete ownership transfer via NFT transfer
- Buyer becomes new owner on blockchain
- One-time payment with royalty to creator
- Permanent ownership change

LICENSING:
- Original owner retains NFT ownership
- Licensee gets usage rights for specified duration
- License recorded in smart contract
- Can be perpetual (duration = 0) or time-limited
- No royalty, only marketplace fee

Q12. What is the purpose of the nonReentrant modifier?
ANSWER: Prevents reentrancy attacks where malicious contracts call back into 
the function before the first execution completes. Critical for functions 
handling ETH transfers like buyTrademark() and licenseTrademark().

SECTION 3: IPFS & DECENTRALIZED STORAGE
================================================================================

Q13. Why did you use IPFS instead of storing files on blockchain?
ANSWER:
- Blockchain storage is extremely expensive
- IPFS provides decentralized, distributed file storage
- Content-addressed: Files identified by cryptographic hash
- Immutable: Hash changes if content changes
- Only IPFS hash stored on-chain (32 bytes vs megabytes of data)
- Cost-effective for images, documents, and metadata

Q14. Explain your IPFS implementation.
ANSWER: Using Web3.Storage (Filecoin-backed IPFS):
- Files uploaded to IPFS via Web3.Storage API
- Returns Content Identifier (CID)
- Metadata JSON also stored on IPFS
- Smart contract stores CID on-chain
- Multiple gateway URLs for redundancy
- Fallback mechanism if one gateway fails

CODE REFERENCE: utils/ipfs.ts

Q15. What is stored on IPFS vs on-chain?
ANSWER:
ON IPFS:
- Trademark images/documents
- Detailed metadata JSON
- File arrays for multiple assets

ON-CHAIN (Blockchain):
- IPFS hash (CID)
- Registration number
- Company name
- Category
- Royalty percentage
- Ownership information
- Transaction history
